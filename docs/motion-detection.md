# 🏃 動体検知

映像の中で動いたところを 32x24 のマスで表示する。顔検出と連動させると、動きがない間は検出の間隔を空けて CPU を減らせる。録画や通知はしない。

## 🔄 処理の流れ

```
FrameArrived (取込スレッド、表示用の書き込みやエンコードの後)
  └─ 輝度を 160x120 に縮小(面積平均)
       → 背景(指数移動平均)との差がしきい値を超えた画素を数える
       → 5x5 画素のマスごとに、変化した画素の割合が CellRatio 以上なら「動いたマス」
       → 動いたマスの割合が MinArea 以上なら「動きあり」。背景を BackgroundRate で更新
```

- 縦方向の足し込みは AVX2(NV12 は Y 面を16画素ずつ ushort に広げ、YUY2 は ushort で読んで下位バイトを取る)。BGRA は (B + 2G + R) / 4 で近似
- 作業領域は最初に確保し、フレームごとの割当はない
- 最初のフレーム、ON にした直後、カメラを開き直した後は背景を作り直す。背景ができるまで(`MotionHoldTime`)は「動きあり」として扱う
- 🖥️ FaceViewer: 動いたマスを 32x24 の WriteableBitmap(1マス = 1画素)に書き、補間なしで引き伸ばして半透明のオレンジで重ねる。UI スレッドへの通知はマスが変わったときだけ
- 🌐 WebStream: クライアントがいるときだけ動かし、結果を WebSocket のヘッダーで送る。配信を遅らせないようエンコードの後で処理するので、ヘッダーには直前のフレームの結果が入る
- 🔗 連動(`Detect:MotionGate`): 最後の動きから `MotionHoldTime` を過ぎたら、顔検出の前処理を `IdleInterval` ごとにだけ行う。止めはしないので、動かない顔も1秒ごとに検出し直す

画面のチェックボックスは「Motion detection」「Detect only on motion」。計測値には Motion(状態と動いたマスの割合)と Motion time が出る。

## 📊 計測結果

動体検知の処理時間(1フレームあたり)

| フォーマット | FaceViewer(平均 / 最大) | WebStream(平均) |
|:--|--:|--:|
| YUY2 640x480 | 0.12〜0.20 / 0.40 ms | 0.15 ms |
| NV12 1280x720 | 0.19 / 0.37 ms | 0.25 ms |
| NV12 1920x1080 | 0.39 / 0.69 ms | 0.32 ms |

YUY2 640x480 は、場面に動きがあると長くなる(判定の分岐が予測しにくくなるため)。

遅延・CPU・割当への影響(YUY2 640x480、顔検出あり)

| アプリ | 動体検知 | Process / 到着→配信可能 | Display latency / 受信(.NET) | CPU | Allocated |
|:--|:--|--:|--:|--:|--:|
| FaceViewer | なし | 0.16 / 0.63 ms | 0.5 / 1.2 ms | 1.34 % | − |
| FaceViewer | あり | 0.16 / 0.48 ms | 0.4 / 1.1 ms | 1.36 % | − |
| WebStream | なし | 1.00 ms | 36.5 ms | 1.36 % | 57 KB/s |
| WebStream | あり | 0.97 ms | 36.3 ms | 1.33 % | 59 KB/s |

FaceViewer の割当は顔枠の描き直しで場面ごとにばらつくので、顔検出なしで比べた: 動体検知なし 104 / 114 KB/s、あり 106 / 110 KB/s(2回ずつ)。

連動の効果(動きのない場面、YUY2 640x480、CPU は全コアに対する割合)

| アプリ | 連動 | 顔検出 | CPU |
|:--|:--|--:|--:|
| FaceViewer | なし | 29.8 fps | 1.49 % |
| FaceViewer | あり | 1.0 fps | 0.31 % |
| WebStream | なし | 29.9 fps | 1.30 % |
| WebStream | あり | 1.0 fps | 0.35 % |

- 動きのない場面は `Motion:Threshold=255`(どの画素も変化とみなさない)で再現
- 人がいる実際の場面では、ほとんどの時間が「動きあり」(動いたマスの割合は5秒ごとの値で 0〜44 %)
- 動いたマスは画面の中ほどにまとまり、照明のちらつきのような横一列の誤検出はなかった(YUY2 640x480 と NV12 1280x720 で各10秒分を集計)

## 💡 分かったこと

- **処理は1フレームあたり 0.1〜0.4 ms**: 大半は縮小(縦方向の足し込み)。差分と判定は 160x120 なので解像度によらない
- **配信・表示の遅延と割当には影響しない**: 表示用の書き込みやエンコードの後に処理するため
- **連動の効果は大きい**: 動きのない場面で顔検出が 30 → 1 fps、CPU は1コアの約31〜36 % から約7〜8 % に減った
- **人がいる場面では効きにくい**: 小さな動きでも「動きあり」になり、`MotionHoldTime` の間は検出を続けるため。誰もいない・動かない時間が長い場面で効く
- **WebStream の動きの結果は1フレーム遅れる**: 顔枠と同じく、配信の遅延を増やさないことを優先した
