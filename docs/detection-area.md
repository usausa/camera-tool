# 🔲 検知範囲

動体検知・顔検出・物体検知を、指定した範囲だけで行う。テレビや窓の外、揺れるカーテンなど、関係のない動きや顔を除くため。範囲は動体検知と同じ 32x24 のマスで持ち、すべての検出で共有する。

- 🏃 動体検知: 範囲外のマスは動いても数えない。動いたマスの割合(`Motion:MinArea` と計測値の Motion の %)は範囲のマス数に対する割合。背景は範囲外も更新し続けるので、範囲を変えても作り直さない
- 🙂 顔検出・📦 物体検知: 枠の中心が範囲外のものを結果から除く(表示にもヘッダーにも出ない)。推論の回数は変わらない
- 🔗 連動: 範囲内の動きだけで判断する。範囲外が動いていても、検出は間隔を空けたまま

## 🖱️ 操作

- 🖥️ FaceViewer: 「Edit area」をオンにすると、マスの線が出て範囲外が暗くなる。ドラッグで、押したマスから今のマスまでの長方形を塗る。押したマスが範囲内なら外し、範囲外なら加える(クリックだけなら1マス)。すぐ判定に反映し、離したときにファイルへ保存する。「Reset area」で画面全体に戻る
- 🌐 ビューアー(WebSocket の表示): 同じ操作を canvas で行う。離したときに `PUT /api/area` でサーバーに反映・保存する。ほかのビューアーは `/api/status` の `areaVersion` の変化で取り直す(1〜2秒以内)
- 範囲が画面全体でないときは、範囲外を薄く暗く表示する(編集中は少し濃く)

💡 小さい範囲を作るときは、画面全体を外すドラッグと、見たい場所を加えるドラッグの2回で済む。

## 💾 保存

範囲はアプリごとの JSON ファイル(`Area:Path`)に保存し、起動時に読む。既定は `%LOCALAPPDATA%` の下なので、Debug と Release で共通。2つのアプリで同じパスを指定すれば共有できる(読むのは起動時だけ)。

```json
{
  "columns": 32,
  "rows": 24,
  "cells": [
    "00000000000000000000000000000000",
    "00000000111111111111111100000000",
    ...
  ]
}
```

- `cells` は上の行から 24 行、1マス1文字(`1`: 範囲内、`0`: 範囲外)。手でも直せる(コメント、末尾のカンマ、BOM も可)
- ファイルがなければ画面全体。形式が違うときは警告をログに出し、画面全体で動く
- 一時ファイルに書いてから置き換えるので、途中で止まってもファイルは壊れない
- 読み書きは2つのアプリで共通(Vision の `DetectionAreaFile`)。WebStream の `GET` / `PUT /api/area` も同じ形
- ⚠️ 書けなかったとき(権限、ほかのアプリのロックなど)は、FaceViewer は画面にエラーを出し、WebStream は `PUT /api/area` に 500 を返してビューアーに表示する。範囲は反映されるが、再起動すると元に戻る
- 解像度やフォーマットを変えても同じ範囲を使う(4:3 と 16:9 では映る範囲が変わるので、少しずれることがある)

## 📊 計測結果(YUY2 640x480)

動体検知の処理時間(1フレームあたりの平均)

| アプリ | 範囲 | 処理時間 |
|:--|:--|--:|
| FaceViewer(顔検出なし、交互に2回ずつ) | 全体 | 0.170 / 0.127 ms |
| FaceViewer(顔検出なし、交互に2回ずつ) | 上半分を外す | 0.150 / 0.130 ms |
| WebStream | 全体 | 0.180 ms |
| WebStream | 左上の一帯(208 マス) | 0.175 ms |

範囲の処理は、96 バイトのマスクの AND とビットの数え上げだけ。

連動の効果(実際の場面、WebStream)

動いたマスを40秒集計し、一度も動かなかった上の3行と左上の一帯(行 3〜10、列 0〜13、計 208 マス)を範囲にした。

| 範囲 | 連動 | 顔検出 | 顔の数 | 動きあり | CPU(1コアあたり) |
|:--|:--|--:|--:|--:|--:|
| 全体 | なし | 29.8 fps | 1.00 | 6/7 | 36.9 % |
| 左上 | なし | 29.9 fps | 0.00 | 1/7 | 38.7 % |
| 全体 | あり | 28.8 fps | 1.00 | 7/7 | 38.7 % |
| 左上 | あり | 1.0 fps | 0.00 | 1/7 | 7.7 % |

- 「動きあり」は5秒ごとの値のうち動きありだった数。左上の 1/7 は起動直後(背景ができるまで)の分
- 配信(到着→配信可能 0.95〜1.06 ms、取込→受信 35.2〜35.5 ms)と割当(34〜37 KB/s)は、どの組み合わせでも同じ
- FaceViewer でも同じ範囲で比べたが、範囲の中にも人の動きがあり(動いたマスの割合 3.5〜5.6 %)、連動時の顔検出は 18.4〜23.9 fps。範囲の中が静かな区間では 1.0 fps
- 割当(FaceViewer、顔検出なし): 動体検知なし 107 / 128 KB/s、動きのない条件(`Motion:Threshold=255`)で動体検知あり 112 KB/s。範囲の処理による増加はない

## 💡 分かったこと

- **範囲は処理時間にも割当にも影響しない**: マスの判定の後にマスクを AND するだけ
- **関係のない動きを範囲外にすると連動が効く**: 人が動く場所を外すと顔検出が 30 → 1 fps、WebStream の CPU は1コアの約39 % から約8 % に減った
- **効果は範囲の中の動きしだい**: 範囲に人が入れば「動きあり」になり、検出は続く。入口など、人の出入りを見張りたい場所を範囲にするのが向いている
- **枠は中心で判定する**: 範囲の境目にかかった顔や物体は、中心の位置で出たり消えたりする
