# 🔌 Web API

WebStream は `http://localhost:5080` で待ち受ける(⚠️ ローカル専用、認証なし)。

## 🗺️ パス

| パス | 内容 |
|:--|:--|
| `/` | ビューアー(表示方式の切り替え、検知の ON/OFF、検知範囲の編集、クライアントとサーバーの計測値) |
| `/ws` | WebSocket 配信(バイナリ: ヘッダー + JPEG。顔検出・動体検知・物体検知の結果もヘッダーに入る) |
| `/ws-h264` | WebSocket 配信(バイナリ: ヘッダー + H.264。ヘッダーは `/ws` と同じ) |
| `/stream.mjpg` | MJPEG(`multipart/x-mixed-replace`)。`<img>` や VLC でそのまま見られる(枠やマスは付かない) |
| `/snapshot.jpg` | 次のフレームを1枚返す |
| `/api/status` | サーバーの計測値(JSON、1秒ごとに更新) |
| `PUT /api/detection` | 顔検出の ON/OFF と、動きとの連動(`{"enabled": true, "motionGate": true}`。指定した項目だけ変わる) |
| `PUT /api/motion` | 動体検知の ON/OFF(`{"enabled": true}`) |
| `PUT /api/objects` | 物体検知の ON/OFF(`{"enabled": true}`) |
| `GET /api/objects/labels` | 物体のクラス名とグループ(`[{"name": "person", "group": "person"}, ...]`。番号はヘッダーのクラス番号) |
| `GET /api/area` | 検知範囲(`{"columns": 32, "rows": 24, "cells": [...]}`。ファイルと同じ形式) |
| `PUT /api/area` | 検知範囲を変える(GET と同じ形式。すぐ反映してファイルに保存。形式が違えば 400) |

`H264:Enable` が `false` のときは、`/ws-h264` は 404 を返す。

## 📨 WebSocket のメッセージ

`/ws` と `/ws-h264` は、バイナリの1メッセージが1フレーム(リトルエンディアン)。

### ヘッダー

| オフセット | 型 | 内容 |
|--:|:--|:--|
| 0 | uint16 | バージョン(1) |
| 2 | uint16 | ヘッダー長(画像データの開始位置) |
| 4 | uint16 | 幅 |
| 6 | uint16 | 高さ |
| 8 | uint32 | 連番 |
| 12 | uint32 | フラグ(bit 0: 顔検出の結果あり、bit 1: 動体検知の結果あり、bit 2: 物体検知の結果あり、bit 3: H.264 のキーフレーム) |
| 16 | float64 | 取込時刻(Unix ms) |
| 24 | float64 | エンコード完了時刻(Unix ms) |

オフセット 32 から、フラグの立っているセクションが顔 → 動き → 物体の順に続く(ないセクションは詰める)。

### 🙂 顔のセクション(bit 0)

| 相対オフセット | 型 | 内容 |
|--:|:--|:--|
| 0 | uint32 | 顔を検出したフレームの連番(0: まだ検出していない) |
| 4 | uint16 | 顔の数 |
| 6 | uint16 | 予約 |
| 8 + 20n | float32 × 5 | 顔枠(左・上・右・下を 0〜1 で正規化)と信頼度 |

### 🏃 動きのセクション(bit 1)

| 相対オフセット | 型 | 内容 |
|--:|:--|:--|
| 0 | uint32 | 動きを判定したフレームの連番(0: まだ判定していない) |
| 4 | uint16 | 動いたマスの数 |
| 6 | uint8 | 列数(32) |
| 7 | uint8 | 行数(24) |
| 8 | byte × 96 | マスク(行優先、各バイトの下位ビットから) |

### 📦 物体のセクション(bit 2)

| 相対オフセット | 型 | 内容 |
|--:|:--|:--|
| 0 | uint32 | 物体を検出したフレームの連番(0: まだ検出していない) |
| 4 | uint16 | 物体の数 |
| 6 | uint16 | 予約 |
| 8 + 24n | float32 × 5 | 枠(左・上・右・下を 0〜1 で正規化)と信頼度 |
| 28 + 24n | uint16 | クラス番号(`GET /api/objects/labels` の順) |
| 30 + 24n | uint16 | 予約 |

### 🖼️ 画像データ

- ヘッダー長の位置から始まる。`/ws` は JPEG、`/ws-h264` は Annex B の H.264 のアクセスユニット
- 顔や物体の数でヘッダーの長さが変わっても、ヘッダー長で読み飛ばせる
- 取込時刻は、カメラのタイムスタンプ(QPC)をサーバーの時計で Unix 時刻に換算したもの。ブラウザーが同じ PC なら、取込から受信・描画までの遅延を測れる

### 🎞️ `/ws-h264` の決まり

- 接続直後は、キーフレーム(bit 3)から送る
- 送信が遅れてフレームを飛ばしたら、次のキーフレームまで送らずに待つ
- クライアントが送ったテキストのメッセージは、すべてキーフレームの要求として扱う(デコーダーのエラーやキューのあふれのときに使う)
- キーフレームには毎回 SPS / PPS が付く。SPS からコーデック文字列(`avc1.4D401E` など)を作れる

## 🎞️ MJPEG のパート

- `Content-Type: multipart/x-mixed-replace; boundary=frame`
- 各 JPEG の直後に、境界と次のパートのヘッダーを書く(ブラウザーが1フレーム早く表示するため。[追加の改善](improvements.md))
- ⚠️ パートに Content-Length はない。境界か、JPEG の SOI / EOI で区切る
