# 🙂 顔検出

RFB-320(入力 320x240)で顔を検出し、枠と信頼度を表示する。検出だけで、誰かの識別はしない。

## 🔄 処理の流れ

```
FrameArrived (取込スレッド)
  ├─ BGRA に変換してトリプルバッファへ → 表示
  └─ 検出器が空いていれば: 320x240 に縮小 + RGB 化 + (x-127)/128 でテンソルへ(前処理)
                            ↓
                     検出スレッド: ONNX Runtime で推論 → しきい値 → NMS → 顔枠を表示
```

- 検出は専用スレッド。処理中に届いたフレームは飛ばすので、取込と表示を待たせない
- IoBinding で入出力を事前に確保したバッファに結ぶ。推論1回の割当は約21バイト
- 顔枠のラベルは子 Visual。文字が変わったときだけ描き直し、位置は `Offset` で動かす

## 📊 計測結果(FaceViewer、変換は Software、表示は Immediate)

| 構成 | 検出 fps | 前処理 | 推論 | Capture latency | Display latency | CPU | Allocated |
|:--|--:|--:|--:|--:|--:|--:|--:|
| YUY2 640x480 検出なし | - | - | - | 33.9 / 48.6 ms | 0.8 / 18.6 ms | 0.30 % | 118 KB/s |
| YUY2 640x480 1スレッド | 29.5 | 0.93 / 1.25 ms | 7.92 / 14.01 ms | 34.0 / 48.5 ms | 0.4 / 1.2 ms | 1.30 % | 208 KB/s |
| YUY2 640x480 2スレッド | 29.5 | 0.99 / 1.18 ms | 6.84 / 9.56 ms | 34.0 / 48.5 ms | 0.6 / 5.2 ms | 5.29 % | 190 KB/s |
| YUY2 640x480 4スレッド | 30.0 | 0.95 / 1.17 ms | 4.49 / 5.96 ms | 34.0 / 48.6 ms | 0.9 / 29.9 ms | 13.48 % | 239 KB/s |
| NV12 1280x720 検出なし | - | - | - | 37.2 / 52.3 ms | 1.0 / 7.6 ms | 0.26 % | 113 KB/s |
| NV12 1280x720 1スレッド | 29.8 | 0.91 / 1.47 ms | 8.36 / 11.53 ms | 37.2 / 52.0 ms | 1.0 / 8.1 ms | 1.58 % | 201 KB/s |

- スレッド数は `Detect:IntraOpNumThreads`
- どの構成も取込・表示は約30fps、GC 0回
- WebStream での計測は [Web 配信](web-streaming.md) の Phase W3

## 💡 分かったこと

- **1スレッドでもカメラと同じ約30fps**(推論 約8 ms)。Capture latency と Display latency は変わらない
- **推論のスレッドを増やすと CPU が大きく増える**: 4スレッドで推論は約4.5 ms になるが、ONNX Runtime のスピン待ちで CPU は約10倍、表示も時々遅れる。既定は1スレッド
- **前処理は約0.9 ms**: 入力は 320x240 固定なので、解像度にほぼ依存しない。後で AVX2 にして約0.3 ms([追加の改善](improvements.md))
- **割当は検出で約 +80〜90 KB/s**(顔枠の更新と Dispatcher)。ラベルを毎回 `FormattedText` で描くと +150〜230 KB/s、図形にして `DrawImage` で描くと約 1.7 MB/s になったので、子 Visual にした
- **モデルは古い形式**: 重みがグラフ入力にも入っていて、ONNX Runtime の定数畳み込みなどが効かない(警告はログレベルで抑えている)。重みを外せば速くなる可能性がある
